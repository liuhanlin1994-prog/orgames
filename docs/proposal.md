# 运筹奇境 → 千里江山·运筹录：改进与重做方案

> 对象：现版本「运筹奇境」（仓库 `operations_research`，外壳 + 9 关）
> 方法：9 关全部用浏览器自动化实际玩通（每关至少一条正常路线、一条烫金路线、一条乱玩路线），并读了关卡源码；随后做了一个水墨风格样章验证新方向。
> 当前进度：已按本方案进入 M1，茶寮、马市、七洲洋三关可玩，见仓库根目录 README 与 `dist/index.html`。

---

## 0. 结论

1. **现版本的短板在关卡设计，不在美术。** 美术平均 7.9 分，好玩 6.1、教学 5.7。9 关里有 6 关的烫金不动脑也能拿到，或者全凭运气；多处结算文案和关卡自己的数据对不上；手机竖屏基本没法玩。
2. **建议重做**，而不是逐关打补丁。要修的是"玩法没有承载概念"这类结构性问题，本来就得把每关的交互重写一遍。既然都要重写，就顺势换成一套我能用代码持续迭代的画风。
3. **新方向：《千里江山·运筹录》。** 画风是程序生成的水墨青绿山水；关卡地图是一幅自右向左展开的手卷；每参透一关，那一段画卷就从水墨"着"上石青石绿，再钤一方印。关卡题材换成中国人熟悉的运筹故事（田忌赛马、华罗庚泡茶、伯乐相马、郑和巡岛……）。
4. 原版的 9 个概念、知识卡文案，以及几处优秀的交互设计全部保留、迁移过来。

## 1. 试玩结论：现版本

### 1.1 做得好的（要保留）

- **完成度高**：大地图、序章 / 终章、图鉴烫金卡、配乐交叉淡入一应俱全；9 关全程**没有一个 JS 报错**。
- **有几处交互是真的好**：
  - 旅行商：拖动航线时实时预览"省 2 天"，本质上就是让玩家亲手做局部搜索。这是全作最好的一关。
  - 排队论：实时调台，失败时队伍排爆的红晕很有冲击力。
  - 背包：金锭"性价比最高却装不满"的陷阱；你 / 贪心 / 最优三个点画在同一张前沿图上。
  - 准入控制：座位卡带剩余时间条；原理页一行 `10 ≥ 50×P(等来豪客)` 就讲清了 Littlewood 法则。
  - 凯利：「命运束」图和增长率曲线（一座山），是全作最好的可视化。
  - 牛鞭：发车按钮直接写"货第 N 周到"，提前期一眼可见。
  - 重复博弈：结尾的生态锦标赛，把一局棋扩展成整个社会的演化。
- **知识卡文案扎实**，可以直接复用。

## 2. 为什么建议重做

- 问题 1–3 都是**玩法层面**的，换皮修不好：要让烫金看方法、让玩家自己撞出结论、让文案和模拟一致，每关的交互和判定都得重写。
- 问题 4 需要**按长宽比重排布局**，而现在的关卡是一张 1000×560 的固定舞台整体缩放，只能推倒重来。
- 既然每关都要重写，就是切换美术管线的最好时机：换成程序生成的画风以后，美术也能像代码一样改参数、反复迭代，不必每次重新生图。

## 3. 关卡设计原则（新旧版本都适用）

1. **玩法即概念。** 核心操作本身就是那个数学结构：旅行商是"落笔连线"，线性规划是"在可行域里拖方案点"，排队是"调门数、看队伍"。
2. **三段式。** 凭直觉做一次 → 碰壁或发现规律 → 用规律再做一次 / 让长卷推演一千次验证。
3. **烫金看方法，不看运气或品行。** 确定性关卡按"与最优解的差距"评级；随机关卡按"把你的策略推演 N 次的期望"评级。
4. **不剧透。** 开场只给目标，不给答案；原理（题跋）在通关后才展开。
5. **文案要和数据一致。** 每关写一个 `simulate()`，文案里的每个数字和结论都由它算出，并写成构建时的检查。比如"凯利最优 40%"、"留 2 座最优"、"先看 37%"，都得先跑自己的模拟验证。
6. **手机竖屏优先。** 布局随长宽比重新生成，不做整体缩放。
7. **一关 3–6 分钟，读字不超过三成。**

## 4. 画风：程序生成的水墨青绿

**做法**（样章里都已实现）：

- 宣纸：纯色底，再用 multiply 叠一层纸纹和纤维。
- 山：一座座单峰成形，前峰压后峰；脊下积墨、折痕、皴擦、苔点、点景树；山脚化入云气留白。
- 点景：屋舍、城墙城楼、虹桥、塔、亭、帆船、马、行人、营帐、梯田、飞瀑，都用几笔画出。
- 笔触：湿笔是变宽的多边形，干笔是多根笔毫断续飞白。航线就用这种笔触"落笔"。
- 上色：同一幅画渲染两层（水墨 / 青绿），通关时用径向遮罩把青绿"晕"开，参照王希孟《千里江山图》的石青、石绿、赭石。
- 题签、印章、竖排题跋：用 CSS 竖排和书法字体。

**为什么适合由我来做**：

- 画风一致：同一套笔法生成全部画面，不会像逐张生图那样风格漂移。
- 可迭代：改一个参数（峰高、皴密度、上色浓度）就能整体调整。
- 体量小：样章单文件 82 KB（gzip 后 29 KB），没有一张图片，国内打开也快。
- 能动：落笔、上色晕开、钤印都是真动画，不是贴图。
- 分辨率无关：手机、4K 屏都清晰；按屏幕比例重新构图也不费事。

**局限与对策**：

- 人物肖像是弱项。对策：沿用山水画"点景人物"的传统，人物只是几笔小像，情绪和叙事交给书法题跋；确实需要立绘时，可以用 AI 生成工笔 / 水墨小品作点缀。
- 配乐：用 Karplus–Strong 算法合成拨弦（近似古琴），在五声音阶上随机游走生成，不需要任何 mp3。样章已实现。
- 字体：标题用马善政毛笔楷（Ma Shan Zheng），正文用思源宋体。Google Fonts 在大陆不稳定，正式版要把用到的字子集化后内嵌（原版已经这样处理了 Cinzel）。

## 7. 样章：七洲洋已经验证了什么

- **三程结构**：
  - 第一程 · 凭直觉：7 个点，玩家落笔连线，立刻和 Held–Karp 算出的精确最短比较，给出"至短 / 上品 / 中品 / 下品"。评级是确定性的，没有运气成分。
  - 第二程 · 解结：12 个点，老舵工画的航线缠成一团。点红圈（交叉）就做一次 2-opt 交换；交叉解完后出现"暗结"（不交叉但换个接法仍能变短）。实测：99 更 → 解开 5 个明结 → 73 更 → 再解 4 个暗结 → 60 更，正好等于最短。
  - 第三程 · 群岛：30 个点，显示可走航线约 4.4×10³⁰ 条。玩家可以自己画，也可以用「就近而行」「解结」两件巧器，结果和多次重启搜索得到的已知最好解一样短。
- **开发中的一个发现**：只解明面上的交叉，结果仍比最短长 22%。于是补上了暗结。这正是原则 5 的例子：结论要先用自己的模拟验证，再写进文案。
- **性能**：7000×900 的长卷分 7 块渐进渲染，桌面端约 1.8 秒画完水墨层；青绿层只在需要时才渲染。
- **手机竖屏**：长卷变成屏幕中部的一条横带；关卡按竖屏比例重新生成岛屿布局。

## 8. 技术方案

- **单页应用**，不再用 iframe：共享 `ink`（笔墨引擎）、`audio`（琴）、`ui`（册页、题签、印章）三个模块；关卡用数据驱动注册。
- **每关一个模块**，统一接口：`setup(stage)`、`simulate(policy, n)`、`grade(result)`、`colophon`。
- **构建**：一个 node 脚本把代码和子集化后的字体内联成单文件，保持原版"丢到任意静态托管就能用"的部署方式。
- **测试**：每关的 `simulate()` 同时用来校验文案里的数字（例如"留 2 座最优"），CI 里跑。
- **存档**：沿用 localStorage，读写都包 try/catch。

## 10. 如果先不重做：原版快修清单（按优先级）
